# 11. Backlog

Главный рабочий документ проекта. Правила декомпозиции обязательны для
каждой задачи:

- одна задача = максимум один рабочий день, реально 2–4 часа;
- ID формата `T-001`, сквозная нумерация через все фазы;
- задачи упорядочены так, что каждая следующая опирается только на уже
  сделанные — предусловия всегда указывают на **меньшие** номера;
- каждая задача заканчивается рабочим состоянием сайта — не бывает
  «полдела сделано, всё сломано»;
- в конце каждой фазы — задача-ревизия: прогон quality gates (docs/10),
  проверка маршрутов на обоих языках, обновление docs/02-routes.md.

## Стандартные критерии приёмки (переиспользуются, не переписываются в каждой задаче)

### СК-Контент — для задач, публикующих текстовую страницу без интерактива

**Критерии приёмки:** страница существует на LV и на RU (если в задаче явно
не указано иное); `route_id` совпадает с docs/02-routes.md; `<title>`/H1
заполнены осмысленным текстом (не placeholder), meta description ≤160
символов; `hreflang` (`lv-LV`/`ru-LV`/`x-default`) и `canonical` корректны;
Schema.org-тип соответствует таблице docs/07-i18n-seo.md §8; внутренние
ссылки на смежные страницы/инструменты не ведут на 404; текст прошёл
редакторское/методическое ревью (не lorem ipsum, не машинный черновик без
правки).

**Как проверить вручную:** открыть обе языковые версии, кликнуть
`LangSwitch` туда-обратно, открыть DevTools → `<head>` → убедиться в наличии
`hreflang`×3 и `canonical`, прогнать Lighthouse SEO локально (`npm run
lighthouse -- --url=...`).

**Definition of Done:** `npm run check` зелёный; контент подтверждён вторым
человеком (редактор/методист) отдельно от автора; строка `route_id` в
docs/02-routes.md обновлена на статус «в проде».

### СК-Инструмент — для задач, реализующих логику или UI инструмента-острова

**Критерии приёмки:** формулы инструмента (если есть, см. `docs/06-tools/*.md`)
покрыты unit-тестами на данных из `/fixtures/`; реализованы все применимые
состояния из docs/04-design-system.md §5 (`default/hover/focus/active/
disabled/loading/empty/error`); JS инструмента собирается в отдельный chunk,
не входит в бандл других страниц; события аналитики из docs/08-analytics.md
для этого инструмента отправляются с верными параметрами; инструмент
полностью управляем с клавиатуры.

**Как проверить вручную:** пройти основной сценарий и минимум один edge case
из соответствующего `docs/06-tools/*.md`; открыть вкладку Network на
странице **другого** инструмента и убедиться, что chunk текущего инструмента
там не загружается; пройти сценарий только клавиатурой (Tab/Enter/Space/
стрелки), без мыши.

**Definition of Done:** `npm run check` зелёный (включая `budget`-гейт);
unit-тесты зелёные; строка в docs/02-routes.md обновлена.
