# Инструмент: Рейтинг школ (`p3-reitings`, Ф2, ★★)

## Вход

Фильтры: город, язык, коробка (аналогично каталогу, подмножество
`CatalogFilters` без `sort` — сортировка в рейтинге **не настраивается
пользователем**, см. критерии приёмки).

## Выход

Ранжированный список школ: позиция, название, `pass_rate` в процентах,
размер выборки, бейдж достоверности (`sufficient`/`limited`/`insufficient`),
ссылка «Как считаем?» → `p3-metodologija`.

## Формула ранжирования

Полностью определена в docs/03-data-model.md, раздел «Правило честности
рейтинга» (нижняя граница интервала Уилсона). Этот документ формулу не
дублирует — только описывает, как она проявляется в UI школьного рейтинга:
агрегат по школе считается по всем инструкторам школы (`sum(exam_attempts)`,
`sum(exam_passes)` по всем `instructors` с данным `school_id`), затем та же
`wilsonLowerBound`.

## Состояния

`default` → `filtered` → `loading` → `no-data-for-subject` (школы без
статистики CSDD — отдельный блок под основным списком, не ранжируются вместе
с остальными и не потому что «плохие», а потому что честно ранжировать не по
чему).

## Edge cases

- Школа с `data_available_for_rating: false` (см. `fixtures/schools.json`,
  `sch-new`) — не попадает в ранжированный список вообще, показывается в
  блоке «Пока нет статистики CSDD» под основным рейтингом.
- FORS может занимать любую позицию, включая последнюю — **UI не имеет
  специального состояния «партнёр» для позиции в рейтинге**, только
  информационный бейдж «Партнёр портала» рядом с названием (не влияет на
  сортировку и не меняет стиль строки).

## Что при пустых данных

`ratings` не рассчитан (первый деплой до первого ETL-прогона) → страница
показывает «Рейтинг пока не рассчитан» вместо пустой таблицы с шапкой.

## Аналитика

`rating_viewed {subject_type: "school"}` · `rating_filter_applied` ·
`rating_methodology_link_clicked` · `rating_low_confidence_badge_viewed
{school_id}`.

## Критерии приёмки

- Порядок строгий по `rank_score`, **не** настраивается пользователем (нет
  переключателя «сортировать по проценту») — это защита от того, чтобы
  честная методика обходилась выбором «неправильной» сортировки в UI.
- Unit-тест на `fixtures/ratings.json`: порядок `sch-x → sch-y → sch-fors`
  (см. docs/03, раздел с числами) воспроизводится компонентом без ручной
  правки.
- Бейдж «Партнёр портала» никогда не меняет визуальный вес строки
  (шрифт/фон/размер) относительно остальных.
