# Инструмент: Рейтинг инструкторов (`p3-instruktori`, Ф2, ★★)

Точная аналогия `rejting-shkol.md`, но на уровне отдельного инструктора, а не
агрегата по школе. Это конкретный экран, детально прорисованный в Модуле 7
(Экран 5) — реализуется в точности по нему.

## Вход

Фильтры из Экрана 5: город, язык, коробка. Список инструкторов, а не школ.

## Выход

Ранжированный список: позиция, имя, `pass_rate` в процентах (визуальный
прогресс-бар `▓▓▓▓▓`), название школы, количество учеников (`sample_size`),
языки. У записей с `confidence: "sufficient"` — `ⓘ Выборка достаточная`; у
записей с `confidence: "insufficient"` — `⚠ Выборка мала — рейтинг
недостоверен` (текст дословно из прототипа).

## Формула

`wilsonLowerBound(exam_passes_total, exam_attempts_total)` напрямую на
уровне инструктора, без агрегации — см. docs/03-data-model.md.

## Состояния

Идентичны `rejting-shkol.md`: `default` → `filtered` → `loading` →
`no-data-for-subject` (инструкторы с `exam_attempts_total: 0`, например
`ins-jauns` в `fixtures/instructors.json`, — вне ранжированного списка).

## Edge cases

Идентичны `rejting-shkol.md`. Дополнительно: один инструктор может работать
на несколько городов/школ в течение выборки — в MVP `city_id`/`school_id`
фиксированные поля (один инструктор = одна текущая школа/город), смена школы
инструктором в течение периода выборки не моделируется отдельно (упрощение,
не баг — если станет проблемой в реальных данных, увидим на этапе ETL и
скорректируем тип).

## Что при пустых данных

Аналогично `rejting-shkol.md`.

## Аналитика

`rating_viewed {subject_type: "instructor"}` · `rating_filter_applied` ·
`rating_low_confidence_badge_viewed {instructor_id}`.

## Критерии приёмки

- Точное воспроизведение примера из Экрана 5 на фикстурах: Бērziņš (71%, 48)
  → Petrova (64%, 31) → Ozols (62%, 27) → … → Lapiņš (100%, 3, с
  предупреждением) — числа и порядок совпадают с `fixtures/ratings.json`.
- Прогресс-бар (`▓▓▓▓▓`) отражает `pass_rate`, а не `rank_score` — визуально
  честно показываем реальный процент, при этом порядок в списке — по
  `rank_score` (это единственная тонкость, которую обязан понимать
  разработчик компонента — см. пояснение в docs/03).
